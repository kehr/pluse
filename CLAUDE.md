# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Pluse is a terminal-based AI assistant for software development built by Charm. It's written in Go and provides multi-model LLM support, LSP integration for code context, MCP (Model Context Protocol) support, and an interactive TUI using the BubbleTea framework.

## Common Commands

```bash
# Build and run
task build                    # Build the binary
go run .                      # Run without building

# Testing
task test                     # Run all tests
go test ./internal/llm/prompt -run TestGetContextFromPaths  # Run single test
go test ./... -update         # Update golden files
task test:record              # Re-record VCR cassettes for agent tests

# Code quality
task lint:fix                 # Run linters and fix issues
task fmt                      # Format with gofumpt

# Development
task dev                      # Run with profiling (PLUSE_PROFILE=true)
task deps                     # Update Fantasy and Catwalk dependencies
```

## Architecture

### Core Package Structure

```
/internal/
├── cmd/           # CLI commands (root, run, logs, schema, login, update-providers)
├── app/           # Application lifecycle and LSP coordination
├── agent/         # Core AI agent logic
│   ├── tools/     # 50+ built-in tools (bash, edit, grep, write, fetch, mcp, etc.)
│   ├── coordinator.go  # Agent coordination and session management
│   └── templates/ # Embedded prompts
├── tui/           # Terminal UI (BubbleTea v2)
│   ├── components/
│   └── styles/
├── config/        # Configuration loading, merging, provider management
├── db/            # SQLite database layer (generated by sqlc)
│   └── migrations/
├── lsp/           # Language Server Protocol client
├── session/       # Session management (services pattern)
├── message/       # Message persistence
├── permission/    # Tool permission management
└── pubsub/        # Event publishing/subscribing
```

### Key Architectural Patterns

- **Services Pattern**: Session, message, and file management use a services abstraction
- **Coordinator Pattern**: Agent coordination through `coordinator.go` for managing conversations
- **Tool System**: Tools are modular and located in `/internal/agent/tools/` - each tool implements a common interface
- **VCR Testing**: Agent tests use VCR cassettes in `/internal/agent/testdata/` for deterministic HTTP replay

### Configuration Resolution

Configuration files are loaded in priority order:
1. `.pluse.json` (project-specific)
2. `pluse.json` (project root)
3. `$HOME/.config/pluse/pluse.json` (user global)

Context paths auto-discovered: `.github/copilot-instructions.md`, `.cursorrules`, `.cursor/rules/`, `CLAUDE.md`, `AGENTS.md`, `pluse.md`, etc.

## Testing Patterns

- Use `testify/require` for test setup assertions, `testify/assert` for test assertions
- Always use `t.Parallel()` for parallel test execution
- Use `t.TempDir()` for temporary directories (auto-cleanup)
- Use `t.SetEnv()` for environment variable setup
- Golden file tests use `.golden` files with `-update` flag to regenerate

### Mock Providers for Testing

```go
func TestYourFunction(t *testing.T) {
    originalUseMock := config.UseMockProviders
    config.UseMockProviders = true
    defer func() {
        config.UseMockProviders = originalUseMock
        config.ResetProviders()
    }()
    config.ResetProviders()
    // test code here
}
```

## Code Style

See `PLUSE.md` for detailed style guidelines. Key points:
- Format with `gofumpt` (stricter than gofmt)
- Use semantic commits: `fix:`, `feat:`, `chore:`, `refactor:`, `docs:`, `sec:`
- JSON tags use snake_case
- File permissions use octal notation (0o755, 0o644)
- Comments on their own lines start with capitals and end with periods

## Environment Variables

- `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GROQ_API_KEY`, etc. - Provider API keys
- `PLUSE_PROFILE=true` - Enable pprof at localhost:6060
- `PLUSE_DISABLE_METRICS=1` - Disable anonymous metrics
- `PLUSE_DISABLE_PROVIDER_AUTO_UPDATE=1` - Disable auto-updating providers

## Database

Uses SQLite with sqlc for code generation. Migrations in `/internal/db/migrations/`. Config in `sqlc.yaml`.
